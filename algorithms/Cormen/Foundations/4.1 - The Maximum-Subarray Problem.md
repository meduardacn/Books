# 4.1 The Maximum-Subarray Problem

## Motivation

Suppose you are offered the chance to invest in the Volatile Chemical Corporation. The stock price is volatile: you can buy one unit once, sell it once at a later date, and you know all future prices. The goal is to maximize profit.

Naively, one might think it suffices to buy at the lowest price or sell at the highest. But the maximum profit does not always come from buying at the lowest or selling at the highest. Counterexample: prices ⟨10, 11, 7, 10, 6⟩ — the maximum profit of $3 comes from buying after day 2 and selling after day 3, not by using the global minimum or maximum.

## Transformation

To design an algorithm faster than O(n²), look at the input differently. Instead of daily prices, consider the **daily change** (price after day i minus price after day i−1). Treat the changes as an array A. We now want to find the **nonempty, contiguous subarray** of A whose values have the largest sum — the **maximum subarray**.

The transformation does not immediately help: there are still Θ(n²) subarrays. The problem is interesting only when the array contains negative numbers — otherwise the entire array is the answer.

## A brute-force solution

Try every possible (buy date, sell date) pair: Θ(n²) pairs, evaluating each in constant time if we organize the computation carefully, for a total of Θ(n²) time.

## A solution using divide-and-conquer

Suppose we want to find a maximum subarray of A[low..high]. Divide it into A[low..mid] and A[mid+1..high]. Any contiguous subarray must lie in exactly one of three places:

- Entirely in A[low..mid].
- Entirely in A[mid+1..high].
- Crossing the midpoint (low ≤ i ≤ mid < j ≤ high).

We find maximum subarrays of A[low..mid] and A[mid+1..high] recursively. We find a maximum subarray *crossing the midpoint* in **linear time** because such a subarray is made of two parts A[i..mid] and A[mid+1..j], each found by sweeping outward from the midpoint.

### FIND-MAX-CROSSING-SUBARRAY

```
FIND-MAX-CROSSING-SUBARRAY(A, low, mid, high)
 1  left-sum = -∞
 2  sum = 0
 3  for i = mid downto low
 4      sum = sum + A[i]
 5      if sum > left-sum
 6          left-sum = sum
 7          max-left = i
 8  right-sum = -∞
 9  sum = 0
10  for j = mid + 1 to high
11      sum = sum + A[j]
12      if sum > right-sum
13          right-sum = sum
14          max-right = j
15  return (max-left, max-right, left-sum + right-sum)
```

For a subarray of n entries, this runs in Θ(n) time.

### FIND-MAXIMUM-SUBARRAY

```
FIND-MAXIMUM-SUBARRAY(A, low, high)
 1  if high == low
 2      return (low, high, A[low])          // base case: one element
 3  else mid = ⌊(low + high)/2⌋
 4      (left-low, left-high, left-sum)   = FIND-MAXIMUM-SUBARRAY(A, low, mid)
 5      (right-low, right-high, right-sum) = FIND-MAXIMUM-SUBARRAY(A, mid+1, high)
 6      (cross-low, cross-high, cross-sum) = FIND-MAX-CROSSING-SUBARRAY(A, low, mid, high)
 7      if left-sum ≥ right-sum and left-sum ≥ cross-sum
 8          return (left-low, left-high, left-sum)
 9      elseif right-sum ≥ left-sum and right-sum ≥ cross-sum
10          return (right-low, right-high, right-sum)
11      else return (cross-low, cross-high, cross-sum)
```

## Analyzing the divide-and-conquer algorithm

Let T(n) be the running time on a subarray of n elements.

- Base case: T(1) = Θ(1).
- Recursive case: two subproblems of size n/2 (2T(n/2)) + crossing-subarray in Θ(n) + constant work.

So T(n) = 2T(n/2) + Θ(n) — the **same recurrence as merge sort**. By the master method (Section 4.5), T(n) = **Θ(n lg n)**.

The divide-and-conquer method is asymptotically faster than the Θ(n²) brute-force approach. Exercise 4.1-5 outlines a **linear-time** (non-divide-and-conquer) algorithm: progress from left to right, maintaining a maximum subarray seen so far. Knowing a maximum subarray ending at index j+1 in constant time given the one ending at j yields the Θ(n) bound.
