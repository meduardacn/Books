# 2.2 Analyzing Algorithms

**Analyzing** an algorithm means predicting the resources it requires — memory, communication bandwidth, hardware — but most often **computational time**. Analyzing several candidate algorithms identifies the most efficient one and discards inferior candidates.

## The RAM model

Before analysis, we need a model of the implementation technology, including its costs. The book assumes a generic one-processor **random-access machine (RAM)** model where instructions execute one after another with no concurrency.

The RAM model contains instructions commonly found in real computers: arithmetic (add, subtract, multiply, divide, remainder, floor, ceiling), data movement (load, store, copy), and control (conditional/unconditional branch, subroutine call/return). Each takes a constant amount of time.

Data types are integer and floating point. We assume a limit on word size: for inputs of size n, integers are represented by c lg n bits for some constant c ≥ 1 (so each word can hold n).

Exponentiation is generally **not** constant-time, but 2^k can be treated as constant time when k is small (via shift-left instruction).

The RAM model does **not** model the memory hierarchy (caches, virtual memory). Other models account for memory-hierarchy effects, but RAM-model analyses are usually excellent predictors of real-machine performance.

## Analysis of insertion sort

The running time depends on the input: sorting a thousand numbers takes longer than sorting three, and even two same-size inputs can take different time depending on how nearly sorted they already are. We describe running time as a function of **input size**.

**Input size** depends on the problem — number of items (for sorting), total bits (for multiplication), vertices and edges (for graphs), etc.

The **running time** on a particular input is the number of primitive operations or "steps" executed. Each line of pseudocode takes constant time cᵢ, though different lines may have different constants.

For INSERTION-SORT, T(n) = c₁n + c₂(n−1) + c₄(n−1) + c₅Σtⱼ + c₆Σ(tⱼ−1) + c₇Σ(tⱼ−1) + c₈(n−1).

**Best case:** Array already sorted. tⱼ = 1, giving a **linear function** of n: T(n) = an + b.

**Worst case:** Array in reverse order. tⱼ = j, giving a **quadratic function** of n: T(n) = an² + bn + c.

## Worst-case and average-case analysis

The book usually concentrates on the **worst-case running time** — the longest running time for any input of size n. Reasons:

- It provides an **upper bound** — a guarantee that the algorithm will never take longer.
- For some algorithms, the worst case occurs fairly often (e.g., searching for absent information).
- The "average case" is often roughly as bad as the worst case. For insertion sort, on average we check half the elements in A[1..j−1] to insert A[j], yielding tⱼ ≈ j/2 and an average-case running time that is also quadratic.

In some cases we use **average-case** running time via **probabilistic analysis**. The scope is limited because it may not be apparent what constitutes an "average" input. Often we assume all inputs of a given size are equally likely. A **randomized algorithm** makes random choices to allow a probabilistic analysis and yield an **expected** running time.

## Order of growth

We make one more simplifying abstraction: it is the **rate of growth**, or **order of growth**, of the running time that really interests us. We consider only the leading term of a formula (e.g., an²), since lower-order terms are relatively insignificant for large n. We also ignore the constant coefficient, since constant factors are less significant than the rate of growth for large inputs.

For insertion sort, the worst-case running time is **Θ(n²)** ("theta of n-squared"). Θ-notation is defined precisely in Chapter 3.

We usually consider one algorithm more efficient than another if its worst-case running time has a lower order of growth. Due to constant factors and lower-order terms, an algorithm with a higher order of growth might take less time on small inputs — but for large enough inputs, an algorithm with a lower order of growth wins.
