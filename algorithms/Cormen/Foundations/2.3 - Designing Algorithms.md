# 2.3 Designing Algorithms

We can choose from a wide range of algorithm design techniques. Insertion sort used an **incremental** approach (insert A[j] into the already-sorted A[1..j−1]). This section examines an alternative: **divide-and-conquer**.

## 2.3.1 The divide-and-conquer approach

Many useful algorithms are **recursive**: to solve a given problem, they call themselves on closely related subproblems. These algorithms typically follow a divide-and-conquer approach:

- **Divide** the problem into a number of subproblems that are smaller instances of the same problem.
- **Conquer** the subproblems by solving them recursively. If subproblem sizes are small enough, solve them in a straightforward manner.
- **Combine** the solutions to the subproblems into the solution for the original problem.

### Merge sort

The **merge sort** algorithm closely follows the divide-and-conquer paradigm:

- **Divide:** Divide the n-element sequence into two subsequences of n/2 elements each.
- **Conquer:** Sort the two subsequences recursively using merge sort.
- **Combine:** Merge the two sorted subsequences to produce the sorted answer.

The recursion "bottoms out" when the sequence has length 1 — trivially sorted.

### The MERGE procedure

The key operation is merging two sorted sequences. MERGE(A, p, q, r) merges two sorted subarrays A[p..q] and A[q+1..r] into a single sorted subarray that replaces A[p..r]. It runs in **Θ(n)** time, where n = r − p + 1.

```
MERGE(A, p, q, r)
 1  n1 = q - p + 1
 2  n2 = r - q
 3  let L[1..n1+1] and R[1..n2+1] be new arrays
 4  for i = 1 to n1
 5      L[i] = A[p + i - 1]
 6  for j = 1 to n2
 7      R[j] = A[q + j]
 8  L[n1+1] = ∞
 9  R[n2+1] = ∞
10  i = 1
11  j = 1
12  for k = p to r
13      if L[i] ≤ R[j]
14          A[k] = L[i]
15          i = i + 1
16      else A[k] = R[j]
17          j = j + 1
```

The idea: place a **sentinel** card with value ∞ at the bottom of each pile so the code does not need to check whether either pile is empty.

### MERGE-SORT

```
MERGE-SORT(A, p, r)
1  if p < r
2      q = ⌊(p + r) / 2⌋
3      MERGE-SORT(A, p, q)
4      MERGE-SORT(A, q + 1, r)
5      MERGE(A, p, q, r)
```

The initial call is MERGE-SORT(A, 1, A.length).

## 2.3.2 Analyzing divide-and-conquer algorithms

When an algorithm contains a recursive call to itself, its running time can often be described by a **recurrence equation** (or **recurrence**), which describes the overall running time on a problem of size n in terms of the running time on smaller inputs.

A recurrence for divide-and-conquer falls out from the three steps. Let T(n) be the running time on a problem of size n. If the problem size is small enough (n ≤ c), it takes constant time Θ(1). Otherwise, with a subproblems of size n/b, dividing in time D(n) and combining in time C(n):

> T(n) = Θ(1) if n ≤ c, or aT(n/b) + D(n) + C(n) otherwise.

### Analysis of merge sort

For merge sort with n > 1:

- **Divide:** D(n) = Θ(1) — just compute the middle.
- **Conquer:** 2T(n/2) — solve two subproblems of size n/2.
- **Combine:** C(n) = Θ(n) — MERGE on n elements.

This yields the recurrence:

> T(n) = Θ(1) if n = 1; T(n) = 2T(n/2) + Θ(n) if n > 1.

The master theorem (Chapter 4) shows T(n) = **Θ(n lg n)**. Because the logarithm grows more slowly than any linear function, for large enough inputs merge sort with Θ(n lg n) running time **outperforms insertion sort**, whose worst-case running time is Θ(n²).

### Intuition via the recursion tree

Rewriting the recurrence as T(n) = c if n = 1; T(n) = 2T(n/2) + cn if n > 1, we expand it into a tree where:

- The root has cost cn.
- The two children are each T(n/2), expanding into cn/2 each, totaling cn at that level.
- Each level totals cn.
- The tree has **lg n + 1 levels**.

Total cost is cn(lg n + 1) = cn lg n + cn, which is **Θ(n lg n)**.
