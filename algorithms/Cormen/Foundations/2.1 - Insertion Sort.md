# 2.1 Insertion Sort

## The sorting problem

- **Input:** A sequence of *n* numbers ⟨a₁, a₂, …, aₙ⟩.
- **Output:** A permutation ⟨a'₁, a'₂, …, a'ₙ⟩ such that a'₁ ≤ a'₂ ≤ … ≤ a'ₙ.

The numbers to sort are also known as the **keys**. The input arrives as an array A of n elements.

Algorithms are described in **pseudocode** similar to C, C++, Java, Python, or Pascal. Pseudocode uses whatever expressive method is clearest and most concise for a given algorithm; sometimes an English phrase is embedded in code. Pseudocode does not concern itself with data abstraction, modularity, or error handling — the goal is to convey the essence of the algorithm.

## The algorithm

**Insertion sort** is efficient for sorting a small number of elements. It works the way many people sort a hand of playing cards: starting with an empty left hand and cards face down on the table, remove one card at a time and insert it into the correct position in the left hand. To find the correct position, compare it with each of the cards already in the hand, from right to left. The hand is always sorted.

```
INSERTION-SORT(A)
1  for j = 2 to A.length
2      key = A[j]
3      // Insert A[j] into the sorted sequence A[1..j-1]
4      i = j - 1
5      while i > 0 and A[i] > key
6          A[i+1] = A[i]
7          i = i - 1
8      A[i+1] = key
```

The algorithm sorts the input numbers **in place**: it rearranges within array A, with at most a constant number of items stored outside the array at any time.

## Loop invariants and correctness

A **loop invariant** is a property that helps us understand why an algorithm is correct. For insertion sort:

> At the start of each iteration of the **for** loop of lines 1–8, the subarray A[1..j−1] consists of the elements originally in A[1..j−1], but in sorted order.

To use a loop invariant to prove correctness, three things must be shown:

- **Initialization:** It is true prior to the first iteration of the loop.
- **Maintenance:** If it is true before an iteration, it remains true before the next iteration.
- **Termination:** When the loop terminates, the invariant gives a useful property that helps show that the algorithm is correct.

This is similar to mathematical induction (with base case and inductive step), except the induction stops when the loop terminates rather than continuing infinitely.

**For insertion sort:**

- **Initialization:** When j = 2, the subarray A[1..1] contains just A[1], which is trivially sorted.
- **Maintenance:** The body of the for loop moves A[j−1], A[j−2], … one position to the right until the proper place for A[j] is found, then inserts A[j]. The subarray A[1..j] then consists of the original elements of A[1..j] in sorted order.
- **Termination:** The for loop terminates when j > A.length = n, so j = n+1. Substituting, A[1..n] consists of the original elements in sorted order — the entire array is sorted, so the algorithm is correct.

## Pseudocode conventions

- **Indentation** indicates block structure.
- Looping constructs **while**, **for**, **repeat-until** and the **if-else** conditional have interpretations similar to C/C++/Java/Python/Pascal.
- After a **for** loop, the loop counter retains the value that first exceeded the bound.
- The keyword **to** is used when the for loop increments; **downto** when it decrements; **by** for steps other than 1.
- "//" denotes a comment.
- Multiple assignments like i = j = e assign e to both i and j.
- Variables are local to their procedure unless explicitly global.
- Arrays are accessed via A[i]; ".." denotes a range, so A[1..j] is a subarray.
- Compound data is organized into **objects** with **attributes**, accessed using dot notation (e.g., A.length).
- A variable representing an array/object is treated as a pointer; the attributes are not copied when the variable is copied. NIL denotes a pointer to no object.
- Parameters are passed **by value** (the called procedure has its own copy). For objects, the pointer is copied but the underlying data is shared.
- A **return** statement transfers control back to the caller and can return multiple values.
- Boolean operators **and** and **or** are **short circuiting**.
- The keyword **error** indicates that conditions were wrong for the procedure to be called; the calling procedure is responsible for handling.
