# 1.2 Algorithms as a Technology

## Why study algorithms even if computers were infinitely fast?

If computers were infinitely fast and memory were free, any correct method would do — but you would still want to demonstrate that your solution method terminates and does so with the correct answer. Since computers are fast but not infinitely fast, and memory is inexpensive but not free, **computing time and space are bounded resources**. Algorithms efficient in time or space help use these resources wisely.

## Efficiency

Different algorithms devised to solve the same problem often differ dramatically in efficiency. These differences can be much more significant than differences due to hardware and software.

**Example: insertion sort vs. merge sort.**

- **Insertion sort** takes time roughly equal to c₁n² to sort n items.
- **Merge sort** takes time roughly equal to c₂n lg n.
- Insertion sort typically has a smaller constant factor (c₁ < c₂), so it runs faster for small inputs. But once n is large enough, the lg n factor of merge sort overcomes any constant-factor advantage of insertion sort. There is always a crossover point beyond which merge sort is faster.

**A concrete comparison.** Imagine running insertion sort on a fast computer A (10¹⁰ instructions/sec, optimized machine-code implementation taking 2n² instructions) against merge sort on a 1000× slower computer B (10⁷ instructions/sec, inefficient high-level implementation taking 50n lg n instructions). To sort 10 million numbers:

- Computer A: 2 · (10⁷)² / 10¹⁰ = 20,000 seconds (more than 5.5 hours).
- Computer B: 50 · 10⁷ · lg 10⁷ / 10⁷ ≈ 1163 seconds (less than 20 minutes).

Computer B runs more than 17 times faster despite being slower hardware with a poor compiler. For 100 million numbers, insertion sort takes more than 23 days while merge sort finishes in under four hours. **As the problem size grows, so does the relative advantage of merge sort.**

## Algorithms and other technologies

Algorithms should be considered a **technology**, just like computer hardware. Total system performance depends on choosing efficient algorithms as much as on choosing fast hardware. Advances are being made in algorithms just as in other technologies.

Other advanced technologies — fabrication, GUIs, object-oriented systems, integrated web technologies, fast networking — do not eliminate the need for algorithms. Even when an application has no explicit algorithmic content at the user level, it still relies on algorithms:

- Hardware design uses algorithms.
- GUI design relies on algorithms.
- Network routing relies heavily on algorithms.
- Compilers, interpreters, and assemblers all make extensive use of algorithms.

Algorithms are at the core of most technologies used in contemporary computers.

Furthermore, with ever-increasing computer capacities, problems being solved are larger than ever before — and differences in efficiency between algorithms become particularly prominent at larger problem sizes.

**Having a solid base of algorithmic knowledge and technique is one characteristic that separates truly skilled programmers from novices.** With modern computing, some tasks can be done without much algorithmic knowledge, but with a good background in algorithms much more becomes possible.
