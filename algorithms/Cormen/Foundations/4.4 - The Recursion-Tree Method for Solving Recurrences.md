# 4.4 The Recursion-Tree Method for Solving Recurrences

Although the substitution method provides a succinct proof that a solution is correct, coming up with a good guess can be hard. Drawing a **recursion tree**, as in the merge-sort analysis, is a straightforward way to devise a good guess.

In a recursion tree, each node represents the cost of a single subproblem somewhere in the set of recursive function invocations. We sum the costs within each level of the tree to obtain a set of per-level costs, then sum all per-level costs to get the total cost of all levels of the recursion.

A recursion tree is best used to **generate a good guess**, which is then verified by the substitution method. When using a tree to generate a guess, one can tolerate a small amount of sloppiness. If careful, one can use the recursion tree as a direct proof.

## Example 1: T(n) = 3T(⌊n/4⌋) + Θ(n²)

Ignore floors and write T(n) = 3T(n/4) + cn² for some c > 0.

- Root cost: cn².
- Three children, each with subproblem of size n/4, so each child contributes c(n/4)².
- Level i has 3^i nodes, each with subproblem size n/4^i and cost c(n/4^i)². The total cost at level i is 3^i · c(n/4^i)² = (3/16)^i cn².
- The tree has height log₄ n + 1 (subproblem size hits 1 when n/4^i = 1, i.e., i = log₄ n).
- The bottom level (leaves) has 3^(log₄ n) = n^(log₄ 3) leaves, each with cost T(1), totaling Θ(n^(log₄ 3)).

Sum across all levels: T(n) = Σ (3/16)^i cn² + Θ(n^(log₄ 3)).

Using the infinite decreasing geometric series as an upper bound: Σ (3/16)^i ≤ 1/(1 − 3/16) = 16/13. So T(n) ≤ (16/13)cn² + Θ(n^(log₄ 3)) = **O(n²)**.

The cost at the root dominates the total cost — the recursion tree is "top-heavy."

We can verify with the substitution method that T(n) ≤ dn² works, requiring d ≥ (16/13)c.

## Example 2: T(n) = T(n/3) + T(2n/3) + cn

Ignore floors/ceilings for simplicity. The tree is unbalanced: one path goes n → 2n/3 → (2/3)²n → … → 1, with length log_(3/2) n.

Each level totals cn (because the costs along each path's level sum to cn — though the tree is not a complete binary tree, the work at each level is still cn until levels near the leaves where work is less).

Intuitively, T(n) is at most the number of levels times the cost of each level: O(cn · log_(3/2) n) = **O(n lg n)**.

A recursion tree is not a complete binary tree, so it has fewer than n^(log_(3/2) 2) leaves. Levels toward the bottom contribute less than cn, but we tolerate this sloppiness when guessing.

**Verification by substitution.** Show T(n) ≤ dn lg n for suitable d > 0:

T(n) ≤ d(n/3) lg(n/3) + d(2n/3) lg(2n/3) + cn
     = dn lg n − d((n/3) lg 3 + (2n/3) lg(3/2)) + cn
     = dn lg n − dn(lg 3 − 2/3) + cn
     ≤ dn lg n

as long as d ≥ c / (lg 3 − 2/3). So a more accurate accounting of costs was not needed.
