# 1.1 Algorithms

## Definition

Informally, an **algorithm** is any well-defined computational procedure that takes some value, or set of values, as **input** and produces some value, or set of values, as **output**. An algorithm is a sequence of computational steps that transform the input into the output.

An algorithm can also be viewed as a tool for solving a well-specified **computational problem**. The problem statement specifies, in general terms, the desired input/output relationship; the algorithm describes a specific procedure for achieving it.

## The sorting problem as an example

- **Input:** A sequence of *n* numbers ⟨a₁, a₂, …, aₙ⟩.
- **Output:** A permutation ⟨a'₁, a'₂, …, a'ₙ⟩ such that a'₁ ≤ a'₂ ≤ … ≤ a'ₙ.

Given the input ⟨31, 41, 59, 26, 41, 58⟩, a sorting algorithm returns ⟨26, 31, 41, 41, 58, 59⟩. Such an input is called an **instance** of the problem. An instance consists of the input needed to compute a solution.

Sorting is fundamental in computer science and many good sorting algorithms exist. Which one is best for a given application depends on factors such as the number of items, how nearly sorted the items already are, restrictions on values, the architecture of the computer, and the kind of storage to be used (main memory, disks, tapes).

## Correctness

An algorithm is **correct** if, for every input instance, it halts with the correct output. A correct algorithm **solves** the computational problem. An incorrect algorithm might not halt at all on some inputs, or might halt with an incorrect answer. Incorrect algorithms can sometimes still be useful if their error rate can be controlled (e.g., algorithms for finding large prime numbers in Chapter 31).

An algorithm can be specified in English, as a computer program, or even as a hardware design — the only requirement is that the specification provide a precise description of the procedure.

## What kinds of problems are solved by algorithms?

Practical applications are ubiquitous. Examples include:

- **The Human Genome Project** — identifying genes in human DNA, storing sequence data, and developing analysis tools.
- **The Internet** — finding good routes for data and using search engines to locate information.
- **Electronic commerce** — relying on public-key cryptography and digital signatures based on numerical algorithms and number theory.
- **Manufacturing and resource allocation** — problems solvable using *linear programming*.

Other specific problems mentioned include:

- **Shortest paths** in a road map modeled as a graph.
- **Longest common subsequence** of two sequences (e.g., to measure similarity of DNA strands), solved efficiently using *dynamic programming*.
- **Topological sorting** for ordering parts in a mechanical design.
- **Convex hull** of n points in the plane.

These problems share two characteristics common to many interesting algorithmic problems: (1) they have many candidate solutions, most of which do not solve the problem, and (2) they have practical applications.

Not every problem solved by algorithms has an easily identified set of candidate solutions — e.g., the **discrete Fourier transform**, computed efficiently by the *fast Fourier transform (FFT)*.

## Data structures

A **data structure** is a way to store and organize data to facilitate access and modifications. No single data structure works for all purposes, so understanding the strengths and limitations of several is important.

## Technique

The book teaches techniques of algorithm design and analysis so the reader can develop their own algorithms, prove correctness, and understand efficiency. Different chapters address different aspects — some focus on specific problems (medians, minimum spanning trees, maximum flow), others on techniques (divide-and-conquer, dynamic programming, amortized analysis).

## Hard problems

Most of the book is about *efficient* algorithms, usually measured by speed. There are some problems, however, for which no efficient solution is known — an interesting subset known as **NP-complete**. Three points make NP-complete problems interesting:

1. No efficient algorithm has been found, but no one has proven that one cannot exist.
2. If an efficient algorithm exists for any one NP-complete problem, then one exists for all of them.
3. Several NP-complete problems are similar, but not identical, to problems for which efficient algorithms are known — small changes in a problem statement can dramatically change the efficiency of the best known algorithm.

Knowing about NP-completeness lets one stop searching for an efficient exact algorithm and instead develop *approximation algorithms* that give a good — but not optimal — solution. The classic example is the **traveling-salesman problem**.

## Parallelism

Physical limits on clock-speed scaling (power density grows superlinearly with clock speed) have led chip designers to add multiple processing **cores**. Multicore computers behave like several sequential computers on a chip — a kind of **parallel computer**. To get the best performance, algorithms must be designed with parallelism in mind. Chapter 27 presents a model for *multithreaded* algorithms that take advantage of multiple cores.
